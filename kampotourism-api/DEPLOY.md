# Deploying Kampotourism API for $0/month

| Piece | Service | Plan |
|---|---|---|
| API (Docker, Java 21) | Render Web Service | **Free** |
| PostgreSQL 16/17 | Neon | **Free** |
| Uploaded images | Cloudinary | **Free** (no card required) |

`render.yaml` (repo root) declares exactly one free web service. It creates no database, disk
or paid add-on.

## Why images go to Cloudinary

Render Free web services have an **ephemeral filesystem** and **no persistent disks**. The
instance also spins down after about 15 minutes without traffic. With the old local storage
(`MEDIA_DIR`), every uploaded image would vanish on the next deploy, restart or spin-down,
while its row in `media_asset` stayed, leaving broken image URLs.

With `MEDIA_STORAGE=cloudinary`:

- An upload is still checked locally first: the file signature must be JPEG, PNG or WebP, the
  image must decode, and it must stay within 12,000 px per side and 40 MP. It is then pushed to
  Cloudinary with a signed request, and the local scratch copy is deleted.
- The database still stores only the key (`2026/11/<uuid>.jpg`). Public URLs become
  `https://res.cloudinary.com/<cloud>/image/upload/<folder>/2026/11/<uuid>.jpg`, served by
  Cloudinary's CDN.
- Replacing or deleting an image deletes the Cloudinary asset and invalidates the CDN cache.
- The API secret is used only to sign requests. It is never sent, logged or shown in errors.

`MEDIA_STORAGE=local` is still the default for development. Startup logs a WARN whenever local
storage is active.

## 1. Neon (database)

1. Sign up at https://neon.tech. No card is needed on the Free plan.
2. **Create project**: choose region **AWS Asia Pacific (Singapore)** to match the Render region.
   The default Postgres version is fine.
3. Open **Connect**, turn **Connection pooling OFF** (the host must *not* contain `-pooler`;
   Flyway needs a direct session), and copy the connection string. It looks like:
   `postgresql://<user>:<password>@<endpoint>.ap-southeast-1.aws.neon.tech/<db>?sslmode=require`
4. Split it into three Render variables. Never put the password inside the URL:
   - `DB_URL` = `jdbc:postgresql://<endpoint>.ap-southeast-1.aws.neon.tech/<db>?sslmode=verify-full&sslfactory=org.postgresql.ssl.DefaultJavaSSLFactory`
     (TLS with certificate and hostname verification against the JVM's trusted CAs).
     If the first deploy fails with a certificate or SSL error, use `?sslmode=require` instead.
     That still encrypts, but does not verify the certificate.
   - `DB_USER` = `<user>`
   - `DB_PASSWORD` = `<password>`

Flyway runs V1 to V6 automatically on first start against the empty database.
`spring.flyway.clean-disabled=true` is set in production, so Flyway can never wipe the schema.
Nothing in this setup resets or drops a database.

## 2. Cloudinary (images)

1. Sign up at https://cloudinary.com/users/register_free. The Free plan needs no card.
2. Go to **Settings → API Keys** (or the Dashboard) and copy the **Cloud name**, **API Key** and
   **API Secret**.

## 3. GitHub

Render deploys from a Git repository. Push this repository to GitHub (a private repo is fine).

## 4. Render (API)

1. Sign up at https://render.com and connect your GitHub account.
2. **New → Blueprint**, select the repository. Render reads `render.yaml`.
3. Fill in the prompted secret values:

   | Variable | Value |
   |---|---|
   | `DB_URL`, `DB_USER`, `DB_PASSWORD` | from step 1 |
   | `ADMIN_EMAIL`, `ADMIN_PASSWORD` | first admin account (password ≥ 12 chars). Only used when no admin exists yet |
   | `CORS_ALLOWED_ORIGINS` | your real frontend origin(s), comma-separated, exact scheme+host, e.g. `https://kampotourism.vercel.app`. No trailing slash |
   | `CLOUDINARY_CLOUD_NAME`, `CLOUDINARY_API_KEY`, `CLOUDINARY_API_SECRET` | from step 2 |

   `JWT_SECRET` is generated by Render (random 256-bit). `SPRING_PROFILES_ACTIVE=prod`,
   `MEDIA_STORAGE=cloudinary` and `CLOUDINARY_FOLDER` are set in the file.
4. Before you click **Apply**, check that the instance type shows **Free**.
5. The first build takes several minutes (Maven runs inside Docker). On the Free instance the
   first boot also takes a while. Wait for `Started KampotourismApplication` in the logs.
6. After the first successful login you can delete `ADMIN_PASSWORD` from the Render environment.
   The admin is already stored (BCrypt) in the database.

**Manual alternative (no Blueprint):** New → Web Service → your repo → Language **Docker** →
Dockerfile path `kampotourism-api/Dockerfile`, Docker build context `kampotourism-api` →
Instance type **Free** → add the variables above plus `SPRING_PROFILES_ACTIVE=prod`,
`MEDIA_STORAGE=cloudinary` and a `JWT_SECRET` from `openssl rand -base64 48` → Advanced →
Health Check Path `/actuator/health/liveness`.

## 5. Verify the deployment

```bash
BASE=https://<your-service>.onrender.com

curl -i $BASE/actuator/health                       # 200 {"status":"UP"} (includes DB check)
curl -i $BASE/actuator/health/liveness              # 200
curl -s $BASE/api-docs | head -c 200                # OpenAPI JSON
# Swagger UI: open $BASE/docs in a browser
curl -s "$BASE/api/v1/destinations?size=3"          # public list, seeded by V2
curl -s "$BASE/api/v1/homepage?lang=en" | head -c 300

curl -i $BASE/api/v1/admin/destinations             # 401 without a token
TOKEN=$(curl -s -X POST $BASE/api/v1/auth/login -H 'Content-Type: application/json' \
  -d '{"email":"<ADMIN_EMAIL>","password":"<ADMIN_PASSWORD>"}' | sed -E 's/.*"accessToken":"([^"]+)".*/\1/')
curl -s $BASE/api/v1/auth/me -H "Authorization: Bearer $TOKEN"                     # role ADMIN
curl -i $BASE/api/v1/admin/settings/homepage -H "Authorization: Bearer $TOKEN"     # 200 (ADMIN only)

# Image upload: the response "url" must start with https://res.cloudinary.com/
curl -s -X POST $BASE/api/v1/admin/media -H "Authorization: Bearer $TOKEN" \
  -F file=@some-photo.jpg -F alt="Test image"
curl -I "<url from the response>"                    # 200 image/jpeg
curl -X DELETE "$BASE/api/v1/admin/media/<id>" -H "Authorization: Bearer $TOKEN"   # clean up
```

## Free-tier behaviour to expect

- **Cold starts**: a Render Free service sleeps after ~15 minutes without traffic. The next
  request wakes it, and a Spring Boot start on a Free instance can take a minute or more.
  Neon also suspends an idle database, which adds about a second on first query. The pool keeps
  0 idle connections and no keepalive on purpose, so Neon can suspend and save free compute hours.
- **Memory**: the image caps the heap at 60% of the 512 MB limit and uses SerialGC and the C1 JIT
  (see `Dockerfile`). Override with a `JAVA_TOOL_OPTIONS` env var if needed.
- **Build minutes**: each deploy builds with Maven inside Docker. Free workspaces have a monthly
  build-minute allowance (see Render → Billing), so avoid unnecessary pushes or turn off
  auto-deploy.
- **Neon storage**: the Free plan storage limit applies to the database only (images are in
  Cloudinary).
- **Login rate limiter**: in memory, so it resets on every restart or spin-down.

## Local development

Copy `.env.example` to `.env` (git-ignored) and fill it in. `application.yml` imports it
automatically, and real environment variables override it.
Run tests with `mvn verify` (needs Docker for Testcontainers).
Build the image with `docker build -t kampotourism-api kampotourism-api/`.
